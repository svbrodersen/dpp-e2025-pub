\section{Generic Reverse-AD of Reduce-By-Index with Invertible Operator}
My code validates and is provided below:
\begin{lstlisting}[language={futhark}]
def vjp_redbyind_inv 't 't_lft [m] [n]
                     (op: t -> t -> t)
                     (op_lft: t_lft -> t_lft -> t_lft)
                     (ne: t_lft)
                     (cfwd: t -> t_lft)
                     (cbwd: t_lft -> t)
                     (op_inv: t_lft -> t -> t)
                     -- \^ function params
                     (dst: [m]t)
                     (ks: [n]i64)
                     (vs: [n]t)
                     (rs_bar: [m]t) : ([m]t, [m]t, [n]t) =
  let hsL = map cfwd vs |> hist op_lft ne m ks
  let hs = map cbwd hsL
  let rs = map2 op dst hs
  let g d h r_bar = vjp (\x -> op x d) h r_bar
  let hs_bar = map3 g dst hs rs_bar
  let dst_bar = map3 g hs dst rs_bar
  let f k v = let p' = op_inv hsL[k] v in vjp (\x -> op x p') v hs_bar[k]
  let vs_bar = map2 f ks vs
  in (rs, dst_bar, vs_bar)
\end{lstlisting}

In the general case of inverting the reduce\_by\_idx we would need multiple
scans. Hinted to via the slides, this could be done by sorting the key-value
pairs according to the keys, but still would be a very expensive operation. In
this special case, we are able to completely circumvent this and simply use
maps only (together with the operator differentiated and inverse). This leads
to an order of magnitudes faster execution than that of the none specialised
method.
